# 项目版本控制与管理技能

## 核心功能

本技能提供完整的项目版本控制能力：
- 版本创建与唯一标识符生成
- 版本回滚功能
- 版本说明强制填写
- 变更记录系统
- **自动版本创建**：检测到项目关键事件后，经用户确认自动创建版本快照

## 工作目录结构

```
project-root/
├── .version-control/
│   ├── versions/           # 版本快照存储目录
│   ├── changelog.json      # 变更记录文件
│   └── current.version     # 当前版本标识
└── [项目文件]
```

## 命令接口

### 1. 创建新版本

**命令格式:** `vc create <版本号> [选项]`

**选项:**
- `-n, --name`: 版本名称（可选）
- `-d, --description`: 版本描述（可选）
- `-f, --features`: 新增功能，用逗号分隔
- `-i, --improvements`: 改进点，用逗号分隔
- `-k, --known-issues`: 已知问题，用逗号分隔
- `-c, --compatibility`: 兼容性信息

**示例:**
```
vc create v1.0.0 -n "初始版本" -f "用户登录功能,数据导入" -i "性能优化" -k "移动端适配待完善" -c "兼容Python 3.8+"
```

### 2. 查看版本列表

**命令格式:** `vc list [选项]`

**选项:**
- `-a, --all`: 显示所有版本
- `-l, --limit <数量>`: 限制显示数量（默认10）

### 3. 查看版本详情

**命令格式:** `vc show <版本号>`

### 4. 版本回滚

**命令格式:** `vc rollback <版本号>`

**注意:** 回滚前会自动创建当前状态的版本快照

### 5. 删除版本

**命令格式:** `vc delete <版本号>`

**注意:** 不能删除当前活跃版本

### 6. 查看变更记录

**命令格式:** `vc changelog [选项]`

**选项:**
- `-f, --from <版本号>`: 起始版本
- `-t, --to <版本号>`: 结束版本

### 7. 自动版本创建配置

**命令格式:** `vc auto [enable|disable|status]`

**自动触发条件:**
- 检测到项目构建成功（如 Maven/Gradle/npm/yarn build 成功）
- 检测到代码提交完成（如 git commit 后）
- 检测到 CI/CD 流水线完成（如 GitHub Actions、GitLab CI 成功）
- 检测到项目部署成功

**自动版本创建流程:**
1. 系统检测到触发事件
2. 自动收集版本信息（提交记录、变更文件等）
3. 向用户发送确认请求
4. **用户确认后**执行版本创建
5. 生成版本快照并记录变更日志

**配置选项:**
- `vc auto enable`: 启用自动版本创建
- `vc auto disable`: 禁用自动版本创建
- `vc auto status`: 查看自动创建状态

## 版本标识符规则

版本号采用语义化版本控制（Semantic Versioning）：
- 格式: `<主版本号>.<次版本号>.<修订号>`
- 示例: `1.0.0`, `2.3.1`

系统会自动生成唯一标识符（UUID），格式为：
- `VER-{UUID前8位}-{时间戳}`
- 示例: `VER-a1b2c3d4-202401151030`

## 版本说明强制字段

创建版本时必须提供以下信息：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| version | string | 是 | 版本号 |
| name | string | 否 | 版本名称 |
| description | string | 否 | 版本描述 |
| features | array | 是 | 新增功能列表 |
| improvements | array | 否 | 改进点列表 |
| known_issues | array | 否 | 已知问题列表 |
| compatibility | string | 是 | 兼容性信息 |
| created_at | datetime | 自动 | 创建时间戳 |
| created_by | string | 自动 | 创建者 |
| commit_hash | string | 自动 | 关联的提交哈希 |

## 版本回滚流程

1. 用户执行 `vc rollback <版本号>`
2. 系统自动创建当前状态的版本快照
3. 从版本库中提取目标版本文件
4. 覆盖当前项目文件
5. 更新当前版本标识
6. 记录回滚操作到变更日志

## 变更记录格式

changelog.json 结构:
```json
{
  "versions": [
    {
      "version_id": "VER-a1b2c3d4-202401151030",
      "version": "1.0.0",
      "name": "初始版本",
      "description": "项目初始版本",
      "features": ["用户登录", "数据导入"],
      "improvements": [],
      "known_issues": ["移动端适配"],
      "compatibility": "Python 3.8+",
      "created_at": "2024-01-15T10:30:00Z",
      "created_by": "user",
      "commit_hash": "abc123"
    }
  ],
  "history": [
    {
      "action": "create",
      "version": "1.0.0",
      "timestamp": "2024-01-15T10:30:00Z",
      "user": "user"
    }
  ]
}
```

## 安全与稳定性保障

1. **原子操作**: 版本创建和回滚采用事务性操作
2. **备份机制**: 每次回滚前自动创建当前状态快照
3. **权限验证**: 重要操作需要确认
4. **日志记录**: 所有操作记录到变更历史
5. **数据完整性**: 使用校验和验证版本文件完整性

## 使用示例

### 创建版本
```
vc create v1.0.0 -n "MVP版本" -f "用户注册,产品列表,订单管理" -i "数据库查询优化" -k "暂无已知问题" -c "兼容Node.js 16+"
```

### 查看版本
```
vc list
```

### 回滚版本
```
vc rollback v0.9.0
```

### 查看变更记录
```
vc changelog -f v1.0.0 -t v2.0.0
```

## 错误处理

| 错误代码 | 错误信息 | 处理方式 |
|----------|----------|----------|
| VC001 | 版本号格式无效 | 检查版本号格式 |
| VC002 | 版本已存在 | 使用其他版本号 |
| VC003 | 版本不存在 | 确认版本号正确 |
| VC004 | 无法回滚到当前版本 | 选择其他版本 |
| VC005 | 缺少必填字段 | 补充必填信息 |
| VC006 | 权限不足 | 联系管理员 |

## 最佳实践

1. 每次重要变更后创建版本快照
2. 填写详细的版本说明便于追溯
3. 在回滚前确认操作影响范围
4. 定期清理不再需要的旧版本
5. 配合Git等版本控制工具使用
